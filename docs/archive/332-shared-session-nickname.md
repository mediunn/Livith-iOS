# [#332] 홈·프로필의 로그인 사용자 상태 공유 — 작업 아카이브

## 결과·범위

앱의 로그인 경로에서 `SessionNickname`을 생성한다. 홈과 프로필에는 그 모델이 가진 닉네임을 전달한다. 첫 서버 조회가 끝날 때까지 닉네임은 비워두며, 실패하면 홈의 기존 새로고침에서 다시 시도한다. 로그인 복원에 필요한 로컬 사용자 확인과 토큰 갱신, 기존 디스크 캐시와 푸시 등록 흐름은 유지한다.

닉네임 수정 Repository가 저장 API 응답의 닉네임을 반환한다. 편집 Store는 저장에 성공했을 때만 해당 값을 공유 상태에 전달한다. 화면 이동은 기존 성공 콜백이 담당한다. 이 변경은 닉네임에 한정하며 홈의 선호 정보 조회와 프로필의 선호 목록 조회를 유지한다.

## 남긴 결정

- App이 세션 모델을 소유하고 홈·프로필 진입점에 표시 값과 필요한 동작을 전달한다. 홈과 프로필은 표시용 닉네임을 따로 저장하지 않는다.
- 첫 조회가 저장 성공보다 늦게 도착해도 저장 응답을 유지한다. 세션 종료 시 닉네임을 지우고 그 세션에 도착한 조회·저장 응답을 무시한다.
- 닉네임은 저장 응답으로 갱신해 화면 재진입이나 추가 프로필 조회에 의존하지 않는다.

## 검증 결과

| 방법·명령 | 기대 신호 | 실제 결과 |
| --- | --- | --- |
| Linux Swift 6 실행 검증 | 초기 공백, 실패 후 재시도, 중복 조회 차단, 저장 응답 우선, 이전 세션과 취소 응답 무시 | `SessionNickname` 실제 소스로 6개 시나리오 통과 |
| Linux 임시 SwiftPM 패키지로 닉네임 편집 테스트 | 가입·수정과 서버 응답 전달 확인 | Combine과 Apple 락 대역을 사용해 17건 통과 |
| Swift 5 언어 모드 Domain 컴파일, 변경 Swift 소스 구문 검사 및 `git diff --check` | 수정 계약, 구문과 공백 검사 | 통과 |
| Xcode 빌드 및 iOS 시뮬레이터 | 홈·프로필 즉시 반영, 자동 로그인, 계정 전환, 푸시 등록 확인 | Linux 실행 환경에서 미실행 |

## 교훈·규칙 반영

- 화면이 사라져도 저장 결과를 공유 상태에 전달할 수 있도록 편집 Store의 성공 처리에 갱신 콜백을 연결했다. 탐색 콜백은 View가 맡는다.

## 미해결·후속 사항

- Mac에서 앱 빌드와 실제 홈·프로필 동작, 자동 로그인과 푸시 등록을 검증한다.
- `User` 전체의 세션 상태 공유, 디스크 캐시 정책과 전역 DI 전환은 후속 범위다.

## 추가 기록

- Xcode Debug 빌드에서 `UserData`의 `MockUserRepository.updateNickname`에 `String` 반환 타입이 빠져 `UserRepository` 채택에 실패했다. 수정 전 소스에서 같은 오류를 재현했고, 반환 타입을 명시한 뒤 실제 Domain 모듈과 Debug mock을 `swiftc -D DEBUG -typecheck`로 검사해 통과했다. 전체 Xcode 빌드는 재확인이 남아 있다.
- 가입 API 응답의 닉네임을 `AuthRepository.signup`에서 반환하도록 변경했다. 가입 성공 시 이 값으로 세션을 초기화하고, 환영 모달과 홈·프로필이 세션의 같은 값을 읽는다. 자동 로그인은 첫 서버 조회까지 이름 없이 표시한다. Linux에서 입력값과 다른 서버 닉네임이 가입 결과로 전달되는지 확인했고, 닉네임 편집 테스트를 포함한 18건이 통과했다. Swift 6 세션 검증에서 가입 시 초기값·중복 조회 생략과 기존 세션 시나리오를 확인했다. 실제 가입과 환영 모달 표시는 iOS에서 확인할 사항이다.
