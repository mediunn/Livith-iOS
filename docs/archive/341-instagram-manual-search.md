# [#341] 인스타그램 수동 공연 검색 ViewModel 전환

## 결과와 결정

매칭 실패와 직접 검색 경로 모두 HomeCoordinator에서 기존 Home Environment의 세 Repository를 전달한다. 수동 검색 화면이 ViewModel을 소유하고 매칭 결과 확인 화면은 기존 Store를 사용한다.

카드를 선택하면 다른 카드의 선택 표시와 등록 버튼의 활성 여부도 바뀐다. [ADR 0002](../adr/0002-viewmodel-ownership.md)에 따라 목록 모델이 선택한 공연 ID 하나를 보관한다. 필터나 페이지가 바뀌어 선택한 카드가 화면에서 사라져도 그 ID로 등록할 수 있다. 이미 관심 공연이면 갱신 요청을 생략한다.

검색어가 바뀌면 SwiftUI가 이전 디바운스 작업을 취소한다. 모델은 진행 중인 검색 페이지 요청을 취소하고, 입력이 바뀐 뒤 도착한 성공·실패 응답을 무시한다. 기본 목록과 검색 목록은 각각 다음 페이지 위치를 유지한다. 포커스와 중단 팝업은 화면이 관리하고, 등록 성공 토스트는 홈으로 돌아간 뒤에도 보이도록 Coordinator에서 표시한다.

## 검증

- Tuist 프로젝트를 생성하고 iOS 26.5 시뮬레이터에서 수동 검색, 매칭 확인, 관심 콘서트 설정 테스트 49개를 통과했다. 수동 검색 테스트는 전역 DI 등록 없이 대역을 직접 전달한다.
- 검색어 삭제 직후의 페이지 응답은 대역에서 보류했다가 반환해 검증했다. 성공·실패 모두 복원한 목록을 유지하며 이전 검색의 오류 토스트가 나타나지 않았다.
- 처음 두 번은 기존 DerivedData에서 테스트 타깃이 새 ViewModel 타입을 찾지 못했다. 별도 DerivedData로 실행해 테스트와 Livith-iOS-Dev 빌드가 성공했다.
- 실기기 확인은 남아 있다. 매칭 실패와 직접 검색으로 각각 진입해 뒤로가기 노출 차이, 중단 팝업에서 계속하기·그만두기, 등록 후 홈 복귀와 성공 토스트를 확인한다.
