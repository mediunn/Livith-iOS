# [#334] 사용자 캐시 제거와 토큰 기반 로그인 복원

## 결과·범위

사용자 조회마다 서버에 요청한다. 5분 메모리 캐시, 사용자 전체를 디스크에 쓰는 코드, 선호 변경 후 캐시를 채우기 위한 재조회를 제거했다. 앱 시작 시 구버전의 `currentUser` 키를 삭제한다. 알림 설정에서 사용자 조회가 실패하면 화면에 표시하던 마케팅 동의 값을 유지한다.

## 남긴 결정

- Keychain 토큰 갱신에 성공하면 메인으로 이동한다. 구버전 사용자 키의 유무와 관계없이 같은 기준을 적용한다. 토큰이 없거나 갱신이 실패하면 로그인 화면을 표시한다. 일시적인 통신 실패만으로 토큰을 삭제하지 않는다.
- 로그인·가입·복원 성공 후 FCM 등록을 시도한다. Firebase 콜백은 메인 화면에서만 재등록으로 이어진다.
- 홈의 화면 상태와 세션의 `SessionNickname`은 유지한다. 홈은 닉네임이 비었을 때만 서버 값으로 채운다. 프로필 저장 응답이 먼저 도착하면 뒤늦은 홈 응답이 그 값을 덮어쓰지 않는다.

## 검증 결과

- iPhone 17 · iOS 26.5 시뮬레이터에서 Tuist 프로젝트 생성과 앱 빌드 성공.
- Xcode 회귀 테스트 142건 통과. 인증 데이터 9건, 홈 56건, 토큰 관리 16건, 닉네임 편집 17건, 알림 데이터 3건, 사용자 데이터 41건. 연속 조회의 두 번째 요청이 실패하면 오류가 전달되고 요청이 두 번 발생하는 경우를 포함한다.
- 격리한 UserDefaults와 토큰 갱신 대역을 사용해 구버전 키 유무와 갱신 성공·실패의 네 조합을 확인했다. 기존 키만 삭제되고 마지막 로그인 수단은 보존됐다.

## 미해결·후속 사항

- 실기기 FCM 등록, 구버전 앱 업데이트와 실계정 로그인 복원, 계정 전환 및 홈·프로필·커뮤니티·알림·선호 화면 수동 확인이 남았다.
- 별도 백로그에서 AppDelegate가 NotificationService와 DeepLinkService를 소유하도록 변경한다. 외부 URL과 푸시 탭, 메인 탭의 대기 링크 소비가 같은 인스턴스를 사용하는지 확인한다.
