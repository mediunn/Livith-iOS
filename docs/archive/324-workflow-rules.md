# [#324] 공통 개발 절차 정비 — 작업 아카이브

## 결과·범위
세 저장소의 공통 Git·계획·검증·문서 언어·ADR 정책과 한국어 산출물 템플릿을 같은 경로와 내용으로 반영했다. 플랫폼별 구현·배포 지침은 분리했다.
CLAUDE.md를 삭제하고 필요한 핵심 지침을 AGENTS.md와 상세 규칙에 남겼다. Tuist·Swift 테스트 도구, Swift 스타일·보안·아키텍처는 보존하고 릴리즈 규칙은 release.md로 분리했다.
앱 코드·의존성·배포 설정과 과거 산출물의 일괄 변환은 제외했다. 이번 작업은 로컬 구현·검증·커밋까지이며 원격 반영은 아직 하지 않았다.

## 남긴 결정
- [ADR 0001: 공통 절차와 플랫폼별 규칙 분리](../adr/0001-common-development-workflow.md)에 사용자와 합의한 선택·대안·영향을 기록했다.
- 계획은 판단이 필요한 작업에 작성하고 미결정 선택에만 사용자 확인을 받는다. 계획의 요구 동작은 기존 규칙·ADR을 자동으로 덮어쓰지 않는다.
- TDD 의무 대신 검증 근거를 요구한다. 계획·트러블슈팅이 생긴 작업만 이슈당 하나로 아카이브한다.
- 일반 작업은 Merge commit, 로컬 커밋은 자율, 푸시·머지·배포는 별도 권한이다. 사소한 수정도 작업 브랜치와 PR을 사용한다.
- 새 아카이브 경로는 docs/archive/다. 기존 iOS docs/archives/ 및 다른 진행 중 문서는 원래 위치에 보존한다.

## 검증 결과
| 방법·명령 | 기대 신호 | 실제 결과 |
|-----------|-----------|-----------|
| git diff --check | 공백 오류 없음 | 통과 |
| 세 저장소 공통 규칙 5개·템플릿 4개·PR 템플릿 비교 | 내용 일치 | 통과 |
| 변경·신규 Markdown 로컬 링크 확인 | 대상 경로 존재 | 통과 |
| Android 계획·PR·브랜치·스킬 길이·문서 표기·보안 검사 | 관련 규칙과 일치 | 통과 |
| Android run_negative_fixtures.py | 정상 사례 통과, 위반 사례 거부 | 통과: 브랜치·커밋·한국어 계획·PR 필수/선택 섹션·아카이브 조건/중복/원본/목록 회귀 사례 |

앱 빌드·기기 검증은 앱·빌드 설정 변경이 없어 미실행했다. 이 결과로 제품 동작이나 실제 운영 배포 성공을 주장하지 않는다. 아카이브 원본 정리 후 조건부 아카이브 검사와 커밋 검사를 확인한다.

## 교훈·규칙 반영
- 같은 정책이 진입점·스킬·검사에 중복됨 → 정본을 연결하고 정책 변경 시 실제 검사까지 함께 확인한다.
- 영어 계획·예전 PR 양식이 검사에 고정됨 → 사용자 산출물 언어와 선택 항목을 검사에도 반영한다.
- 이번 대화에서 승인한 정책만 반영했다. 추가로 제안해 적용한 보안·아키텍처 변경은 없다.
- 제품 구현·검증 상태가 바뀌지 않아 engineering-notes·tracking/status의 제품 상태를 변경하지 않았다.

## 미해결·후속 사항
- 푸시·PR 생성·머지·배포는 미실행이다. 현재 이슈를 닫지 않는다.
- Web의 실제 Vercel 운영 브랜치·도메인·중복 연결 상태·롤백 절차는 로그인한 대시보드에서 후속 확인이 필요하다.
- Web의 ESLint 모듈 형식, Prettier 설정 적용, npm lockfile과 Chromatic yarn 설치의 불일치는 별도 후속 작업이다.
- 과거 문서·기록의 언어·파일명은 변경하지 않는다. 공통 규칙 후속 변경 시 다른 저장소 반영 필요성을 확인한다.
