### 2026-07-27 20:54 - 변경 관련 테스트만 실행할 것

**상황**
- 말줄임·Store 수정 후 `HomeFeatureTests` 타겟 전체를 반복 실행했다.

**문제**

**원인**

**교훈**
- TDD 루프에서는 현재 실패·보호 테스트 범위만 실행한다. 타겟 전체를 습관적으로 돌리지 않는다.
- 승격 후보: yes → `tdd.md`에 범위 규범 반영, `project-operations.md`에는 `-only-testing` 문법만 유지

### 2026-07-27 20:52 - 말줄임 문자를 U+2026 대신 ASCII `...`로 변경

**상황**
- 요청 결과 카드 말줄임이 글자 세로 중앙에 떠 보였다.

**문제**
- 베이스라인(아래)에 붙어야 하는데 가운데 정렬된 점처럼 보였다.

**원인**
- `…`(U+2026) 글리프가 Noto Sans에서 세로 중앙에 배치된다.

**해결**
- 말줄임을 ASCII `...`로 바꿔 베이스라인에 붙인다. (칩 등 기존 패턴과 동일)

**교훈**
- UI 말줄임은 폰트 글리프 위치를 확인하고, 필요하면 `...`를 쓴다.
- 승격 후보: no

### 2026-07-27 20:49 - 요청 결과 공연명 말줄임 기준을 공백 포함 24자로 정정

**상황**
- Figma 플레이스홀더 `[19자 내 공연명 이후 말줄임..] 콘서트`를 목에 넣으니 코드가 19자로 잘라 `..`와 `…`가 겹쳤다.

**문제**
- 말줄임 한도가 19자로 되어 있어 Figma 표기(플레이스홀더 전체 24자)와 어긋났다.

**원인**
- Figma 문구의 `19자`를 한도로 해석했다. 실제 플레이스홀더 문자열 길이는 공백 포함 24자이다.

**해결**
- `requestConcertNameMaxLength`를 24로 변경하고 테스트를 갱신했다. 목 타이틀은 Figma 원문을 유지한다.

**교훈**
- Figma 플레이스홀더 숫자는 한도가 아닐 수 있다. 표시 문자열 길이와 주석을 함께 확인한다.
- 승격 후보: no

### 2026-07-27 20:47 - 목 타이틀을 임의 공연명으로 바꾸지 말 것

**상황**
- Figma 플레이스홀더 타이틀의 `..`과 코드 말줄임 `…`이 겹친다고 확인해 달라고 했다.

**문제**
- `..`만 지우라고 했는데, 타이틀 전체를 임의 공연명으로 바꿨다.

**원인**
- “말줄임 동작만 보려면 실제 공연명” 제안을 승인(“그래”)으로 해석하고 문구 자체를 교체했다.

**해결**
- 원래 문구를 유지하고 `..`만 제거: `[19자 내 공연명 이후 말줄임] 콘서트`

**교훈**
- 문구 수정은 요청 범위를 넘지 않는다. 지정 문자열에서 문제 구간만 고친다.
- 승격 후보: no

### 2026-07-27 20:30 - 취소된 관심 목록 결과가 재조회 로딩을 꺼버리는 순서 버그

**상황**
- 구현 후 코드 점검 중 `_interestListResult` 처리 순서를 검토했다.

**문제**
- `isInterestListRetryLoading = false`를 cancellation 체크보다 먼저 수행하면, 재조회 중 이전 Task 취소 결과가 로딩을 끄고 엠티뷰가 잠깐 보일 수 있다.

**원인**
- 재조회 로딩 해제와 cancellation early return 순서를 분리하지 않았다.

**해결**
- cancellation이면 상태를 건드리지 않고 return한다. 비취소 결과에만 `isInterestListRetryLoading`을 해제한다.
- 목록이 있는 실패 분기에서 불필요한 `isInterestListLoadFailed = false` 대입을 제거했다.

**교훈**
- 재시도 로딩 플래그는 취소 결과에서 끄지 않는다. 최신 요청 완료에서만 끈다.
- 승격 후보: no
