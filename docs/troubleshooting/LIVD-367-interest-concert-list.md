# LIVD-367 관심 콘서트 목록 화면 - 트러블슈팅

## 기록

### 2026-05-01 02:00 - 컬렉션 네이밍 규칙 누락

**상황**
- `InterestConcertGridView`를 `InterestConcertListView`로 변경하면서 정렬 옵션 컬렉션 이름을 `listOptionList`로 바꿨다.
- 사용자가 `listOptionList`가 마음에 들지 않는다고 피드백했다.

**문제**
- 처음에는 `sortOptions`가 자연스럽다고 제안했지만, 프로젝트 코드 컨벤션은 배열/목록 컬렉션에 단순 복수형보다 `List` 접미사를 우선하도록 정하고 있다.

**원인**
- 네이밍 제안 전에 `docs/rules/code-convention.md`의 Naming 규칙을 다시 확인하지 않았다.

**해결**
- 정렬 옵션 목록이라는 의미와 `List` 접미사 규칙을 모두 만족하도록 `sortOptionList`로 정정한다.

**교훈**
- 컬렉션 네이밍을 제안하거나 변경할 때는 자연스러운 영어 표현만 기준으로 삼지 않고, 프로젝트의 `List` 접미사 규칙을 먼저 적용한다.

---

### 2026-05-01 01:34 - MARK 정리 후 불필요한 테스트 재실행

**상황**
- 빈/오류 상태 구현 후 테스트가 통과했고, 서브에이전트 리뷰에서 제안한 MARK 섹션 정리만 추가로 반영했다.

**문제**
- 기능 변경이 아닌 MARK 주석 위치 변경 후 전체 테스트를 다시 실행했다.

**원인**
- 변경 성격을 구분하지 않고 이전 검증 루틴을 그대로 반복했다.

**해결**
- 사용자가 테스트 실행을 중단했고, MARK 주석 정리만으로는 테스트 재실행이 불필요하다고 판단을 정정했다.

**교훈**
- 기능/동작 변경이 아닌 주석, MARK 섹션, 문서성 정리만 수행한 경우에는 직전 기능 검증 결과를 유지하고 테스트를 반복 실행하지 않는다.

---

### 2026-05-01 01:33 - 테스트 번들 로드 시 Amplitude 서명 실패

**상황**
- 빈/오류 상태 구현 후 `tuist test HomeFeature --no-selective-testing`로 검증을 시도했다.

**문제**
- 빌드는 완료되었지만 테스트 번들 로드 단계에서 `Amplitude.framework`가 unsigned library로 판단되어 테스트가 실패했다.

**원인**
- DerivedData 또는 Tuist 캐시의 서명된 산출물 상태가 불안정해진 것으로 추정된다.

**해결**
- 미해결. clean 재실행으로 검증을 다시 시도한다.

**교훈**
- 빌드 성공 후 테스트 번들 로드에서 외부 프레임워크 서명 오류가 발생하면 코드 변경 문제와 분리해 캐시/DerivedData 재생성을 우선 확인한다.

### 2026-05-01 00:00 - 계획 문서 이슈 번호 오기입

**상황**
- 관심 콘서트 목록 화면 구현 계획 문서를 작성했다.

**문제**

**해결**
- 현재 브랜치 `feat/LIVD-367-interest-concert-list-ui`를 확인한 뒤 계획 문서 파일명과 제목을 `LIVD-367`로 수정했다.

**교훈**
- 계획 문서를 작성하기 전에는 먼저 현재 브랜치명을 확인해 이슈 번호를 확정한다.
