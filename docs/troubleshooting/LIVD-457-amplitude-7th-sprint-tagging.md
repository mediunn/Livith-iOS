# LIVD-457 7차 스프린트 앰플리튜드 태그 태깅 - 트러블슈팅

## 기록

### 2026-07-25 - 캘린더 이벤트 태깅 가능 범위 재판단

**상황**
- 초기 계획에서 캘린더 관련 "01. 태깅 요청" 7개 이벤트 전체를 `CalendarWebView`(빈 WKWebView) 때문에 태깅 불가로 분류했다.

**문제**
- "캘린더도 시도" 방침 확인 후 재조사하니, 캘린더 화면이 전부 WebView가 아니었다.

**원인**
- `CalendarHomeContentView`는 네이티브 `CalendarFilterBarView`(칩/스코프 필터) + `CalendarWebView`(그리드) 조합이었다. 초기엔 그리드만 보고 전체를 WebView로 오판했다.

**해결**
- 필터바의 4개(공연일/예매일 칩, 전체/내 공연 스코프)는 네이티브 `onTap` 클로저에 태깅 지점이 있어 반영했다.
- 그리드 인터랙션(월 이동/오늘/일자 클릭) 3개만 WebView 내부라 제외로 유지했다.

**교훈**
- "WebView라 불가"로 단정하기 전에 화면을 구성 컴포넌트 단위로 분해해 네이티브/웹 경계를 확인한다.

---

### 2026-07-25 - `EventTag.value` 검증 테스트(TDD) 방침 변경

**상황**
- 계획에서 신규 이벤트 raw 값 오타 방지를 위해 `EventTag.value` 검증 테스트를 TDD로 먼저 작성하려 했다.

**문제**
- Amplitude 모듈은 물론 Core 프로젝트 전체에 단위 테스트 타깃이 하나도 없었다.

**원인**
- `Projects/Core/Project.swift`에 테스트 타깃 정의가 없고, 추가하려면 공유 Tuist 타깃 enum(`TargetName`)까지 신규 케이스를 넣어야 해 변경 파급이 컸다.

**해결**
- `tdd.md` 범위상 enum 상수 데이터 추가와 뷰의 트랙 호출 삽입은 도메인/스토어 로직이 아닌 UI/데이터 배치로 TDD 예외에 해당한다고 판단, 테스트 타깃 신설 없이 진행했다.
- raw 값은 명세서와 문자 단위로 대조하고 `tuist build`로 컴파일을 보증했다.

**교훈**
- TDD 적용 전에 대상 모듈의 테스트 인프라 존재 여부와 `tdd.md` 적용 범위를 먼저 확인한다. 인프라 신설이 변경 목적에 비해 과도하면 규칙의 예외 조항을 근거로 결정하고 문서로 남긴다.
