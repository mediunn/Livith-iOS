# LIVD-363 회원가입 API 및 유저 도메인 모델 수정 - 트러블슈팅

## 기록

### 2026-04-28 18:49 - 1단계 리뷰 피드백 공백 라인 정리

**상황**
- 1단계 구현 후 서브에이전트 최종 리뷰를 요청했다.

**문제**
- `OnboardingFeatureDTOTests.swift`에 공백만 포함된 빈 줄이 남아 있다는 리뷰 피드백을 받았다.

**원인**
- 기존 테스트 파일의 공백 라인을 신규 테스트 추가 과정에서 함께 정리하지 못했다.

**해결**
- 공백-only 빈 줄을 일반 빈 줄로 정리했다.
- 서브에이전트 재리뷰에서 공백 문제 해결을 확인했다.

**교훈**
- 리뷰 피드백으로 수정한 내용은 코드 수정뿐 아니라 트러블슈팅 문서에도 최신순으로 기록한다.

---

### 2026-04-28 18:45 - 1단계 실패 테스트 대신 보호 테스트 적용

**상황**
- 1단계 회원가입 API 수정 계획에 따라 변경된 `DTO.Response.Signup` 응답 테스트를 먼저 추가했다.

**문제**
- 신규 테스트가 실패하지 않고 통과했다.
- 계획 문서의 기존 작업 항목은 실패 테스트 작성을 요구했으나, 실제 생산 코드는 이미 `DTO.Response.Signup.user`가 `DTO.Response.FetchUserInfo`를 재사용하고 있어 `providerId` nullable과 `hasPreferredGenre`를 처리하고 있었다.

**원인**
- 1단계 대상 API 스펙 일부가 작업 시작 전 코드에 이미 반영되어 있었다.

**해결**
- 사용자 확인 후 1단계 첫 작업 항목을 실패 테스트가 아닌 기존 구현 충족 확인 및 보호 테스트 추가로 조정했다.
- 생산 코드 변경 없이 회원가입 전체 응답 디코딩 보호 테스트를 추가했다.

**교훈**
- TDD red가 성립하지 않는 경우 임의로 실패를 만들지 않고, 기존 구현 충족 여부를 기록한 뒤 보호 테스트로 회귀를 막는다.

### 2026-04-28 18:43 - xcodebuild destination OS 불일치

**상황**
- Swift Testing 실행 여부를 더 명확히 확인하기 위해 `xcodebuild test`를 직접 실행했다.

**문제**
- `OS=26.4`로 destination을 지정했지만 사용 가능한 iPhone 17 시뮬레이터는 `OS=26.4.1`이라 테스트가 실행되지 않았다.

**원인**
- `simctl` 출력의 런타임 표시와 `xcodebuild` destination 표시의 patch 버전이 달랐다.

**해결**
- `xcodebuild`가 출력한 사용 가능한 destination 값에 맞춰 `OS=26.4.1`로 재실행한다.

**교훈**
- `xcodebuild test` destination은 실패 출력의 Available destinations 값을 기준으로 정확히 지정한다.

### 2026-04-28 18:40 - Swift Testing 테스트 실행 집계 불명확

**상황**
- `tuist test LivithNetwork`와 `tuist test AuthData`를 실행해 Swift Testing 기반 테스트를 검증했다.

**문제**
- 두 명령 모두 성공했지만 Xcode 출력은 `Executed 0 tests`로 표시되어 테스트 discovery와 실행 여부가 불명확했다.

**원인**
- 원인 미파악. 현재 Tuist/Xcode 조합에서 Swift Testing 테스트 집계가 XCTest 실행 요약에 반영되지 않는 것으로 보인다.

**해결**
- `xcodebuild test`와 결과 번들 확인으로 실행 여부를 추가 검증한다.

**교훈**
- Swift Testing 기반 테스트는 단순 성공 여부뿐 아니라 실행 개수 또는 결과 번들에서 테스트 식별자를 확인한다.

### 2026-04-28 18:38 - LivithNetworkTests 스킴 없음

**상황**
- 1단계 회원가입 응답 DTO 테스트 추가 후 `tuist test LivithNetworkTests`로 테스트 실행을 시도했다.

**문제**
- Tuist가 `LivithNetworkTests` 스킴을 찾지 못해 테스트가 실행되지 않았다.

**원인**
- 이 저장소의 Tuist 스킴 목록에는 테스트 타겟명이 아닌 `LivithNetwork` 스킴이 노출되어 있다.

**해결**
- `tuist test LivithNetwork`로 관련 스킴 테스트를 다시 실행한다.

**교훈**
- 테스트 실행 전 Tuist 출력의 사용 가능한 스킴명을 기준으로 명령을 조정한다.
