# [LIVD-427] livith-design-pipeline 스킬 추가 - 트러블슈팅

## 기록

### 2026-07-08 10:55 - 기능명세 반영 지원 추가 피드백

**상황**
- 스킬 초기 버전은 Figma에서 디자인(레이아웃·스타일)만 수집하도록 작성했다.

**문제**
- 이 프로젝트의 Figma 파일은 디자인 옆에 기능명세가 함께 배치되어 있는데, 스킬이 이를 수집·반영하지 않았다. 사용자가 기능명세도 함께 반영되도록 요청했다.

**원인**
- 참고한 파이프라인 구조가 디자인 대조 중심이어서, 이 프로젝트의 Figma 운영 방식(디자인+명세 병행 배치)을 확인하지 않고 그대로 따랐다.

**해결**
- SKILL.md Step 1에 기능명세 수집 단계, Step 2에 `spec` 필드와 touchesLogic 판정 규칙을 추가하고, 워크플로우 프롬프트(수정/TDD/대조)에 명세 반영을 포함했다.

**교훈**
- 파이프라인 스킬을 만들 때는 대상 프로젝트의 Figma 파일 구성(명세 포함 여부)을 먼저 확인하고 수집 범위를 정한다.

### 2026-07-08 10:47 - 스킬 이름 변경 및 참고 저장소 언급 제거 피드백

**상황**
- `figma-to-pr`이라는 이름으로 스킬(SKILL.md)과 워크플로우 스크립트를 작성하고, 계획 문서 배경에 참고한 외부 저장소(Mino-harness) 링크를 남겨두었다.

**문제**
- 사용자가 스킬 이름을 `figma-to-pr`이 아닌 다른 이름으로 바꾸고, 배경의 Mino-harness 언급도 제거하라고 피드백했다.

**원인**
- 참고 저장소의 파이프라인 이름과 출처를 그대로 노출한 초기 결정이 사용자 의도(자체 스킬로 정착)와 달랐다.

**해결**
- 스킬 디렉토리·워크플로우 파일·계획 문서를 `livith-design-pipeline`으로 일괄 변경하고, 모든 산출물에서 Mino-harness 언급을 제거했다. 잔여 참조는 grep으로 확인했다.

**교훈**
- 외부 저장소를 참고해 산출물을 만들 때는 이름과 출처 표기를 프로젝트 컨벤션(기존 스킬 네이밍 `livith-*`)에 맞출지 사용자에게 먼저 확인한다.
