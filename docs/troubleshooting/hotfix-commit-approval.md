# hotfix 커밋 승인 누락 - 트러블슈팅

## 기록

### 2026-05-02 - 커밋/푸시 사용자 승인 누락

**상황**
- 사용자가 "마이페이지 버전 정보 1.1.0으로 바꿔"라고만 요청
- 코드 수정 후 사용자 명시 승인 없이 바로 커밋 + develop에 직접 push 진행

**문제**
- 사용자는 코드 수정만 요청했는데 자동으로 커밋/푸시까지 진행됨
- 사용자가 변경 내용을 검토할 기회를 갖지 못한 채 원격에 반영됨
- 이전 hotfix 작업(앱 버전 1.1.0 변경)에서도 동일하게 사용자 승인 절차 생략

**원인**
- "수정 → 커밋 → 푸시"를 하나의 흐름으로 자동 진행하는 습관
- `git.md`에 커밋/푸시 시점의 사용자 승인 규칙이 명시되지 않아 우회의 여지가 있었음
- CLAUDE.md의 BLOCKING REQUIREMENT에도 커밋 승인 항목이 누락되어 있었음

**해결**
- `docs/rules/git.md` Do 섹션 최상단에 "사용자 승인" 항목 추가
  - 커밋/푸시는 사용자가 "커밋해", "푸시해"처럼 명시적으로 지시한 경우에만 진행
  - 사용자가 코드 수정만 요청한 경우 빌드 검증 후 변경 내용 보고하고 승인 대기
  - amend/force push 등 히스토리 변경도 동일하게 승인 필요

**교훈**
- 사용자가 "수정해"라고만 했을 때는 수정만 한다. 커밋/푸시는 **명시적 지시**가 있을 때만 한다.
- 작업 흐름을 "수정 → 보고 → 승인 대기"로 끊고, 승인을 받은 뒤에만 git 액션을 수행한다.
- 규칙이 명문화되지 않으면 동일한 패턴이 반복되므로, 발견 즉시 규칙 문서에 반영한다.
