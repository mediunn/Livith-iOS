# ADR 0001: 공통 개발 절차와 플랫폼별 규칙 분리

## 상태
승인 — 2026-11-16. 관련 이슈: #324.
이번 사용자 대화에서 정책을 선택하고 이슈 생성·구현 진행을 승인했다.

## 배경
프론트엔드 개발자 한 명이 Web·iOS·Android를 유지보수한다. 저장소마다 규칙·문서·작업 조건이 달라 전환할 때마다 절차를 다시 익혀야 했다.

## 검토한 대안
| 대안 | 장점 | 비용 |
|------|------|------|
| iOS 규칙 전체 복제 | 빠르게 일치 | 웹 배포·Android 구현과 미배포 상태에 맞지 않음 |
| 저장소별 독립 절차 유지 | 개별 최적화 | 형식·순서 재학습과 규칙 충돌 지속 |
| 공통 절차와 플랫폼별 지침 분리 | 같은 흐름으로 작업하며 구현 특성 보존 | 공통 규칙 변경 시 저장소 간 반영 확인 필요 |

## 결정과 이유
- 세 번째 대안을 선택한다. 공통 규칙은 각 저장소의 같은 경로에 두고 중앙 의존성이나 동기화 시스템은 추가하지 않는다.
- 사용자 검토용 계획·트러블슈팅·아카이브·신규 ADR·이슈·PR은 한국어다. 규칙·스킬은 영어도 허용한다.
- 계획은 사전 판단이 필요한 작업에 작성한다. 미결정 선택만 사용자 확인을 받고, 합의된 계획은 바로 실행한다.
- 계획의 목표·범위가 작업 요구의 최신 기준이다. 규칙·ADR 충돌은 별도 사용자 결정을 받는다.
- TDD를 강제하지 않고 변경에 맞는 검증과 실제 근거를 요구한다.
- 계획·트러블슈팅이 생긴 작업만 이슈당 하나로 아카이브한다. 보존 확인 뒤 원본을 정리하고 규칙 변경은 별도 확인한다.
- 일반 PR은 Merge commit으로 반영한다. 로컬 커밋은 자율 수행하되 푸시는 명시적 지시가 필요하다. 머지·배포 권한은 별개다.
- 동작에 영향 없는 사소한 수정은 이슈 없이 작업 브랜치·PR을 사용한다. 핫픽스는 별도 절차와 명시적 긴급 예외를 적용한다.
- PR은 최종 변경·이유·검증 중심이며 복잡한 작업에만 완료 조건 대응표를 추가한다.
- `AGENTS.md`를 단일 진입점으로 쓰고 `CLAUDE.md` 중복 지침을 두지 않는다.

## 영향·트레이드오프
플랫폼별 아키텍처·보안·검증 도구·배포는 유지한다. 자동 동기화가 없어 공통 규칙 변경 시 다른 저장소 반영 필요성을 기록해야 한다. 과거 산출물은 일괄 변환하지 않는다.
