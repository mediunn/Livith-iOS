# Swift 테스트 작성

검증 선택과 테스트 순서는 [공통 검증 규칙](testing.md)을 따른다. 이 문서는 TDD를 의무화하지 않는다.

- 도구·필터·테스트 집계 확인은 [프로젝트 운영](project-operations.md)을 따른다.
- 새 테스트 파일·타입은 Swift Testing을 우선한다. 기존 XCTest 파일 전체를 이번 변경과 무관하게 전환하지 않는다. 기존 XCTest 타입에 새 테스트를 추가하는 대신 필요한 새 테스트는 Testing 타입으로 둔다.
- `@Test`, `@Suite` 제목은 검증할 행동을 한국어로 설명한다. 식별자는 기존 코드 규칙을 따른다.
- 테스트는 단일 대상의 상태·결과·필요한 부수효과를 검증한다. 긴 준비·행동·검증 구간은 Given/When/Then으로 구분한다.
- 실행할 때 대상 모듈의 테스트 타깃과 scheme action을 확인한다. 컴파일 성공과 실제 테스트 실행 성공을 구분한다.
- TDD를 선택하면 기대한 동작 부재로 실패했는지 확인한다. 컴파일 오류를 행동 실패의 증거로 취급하거나 이미 통과하는 동작을 억지로 실패시키지 않는다.
- 테스트 편의를 위해 생산 코드 생성자·공개 인터페이스에 전용 매개변수를 추가하지 않는다. 필요한 추상화 변경은 사용자와 결정한다.
