# [LIVD-427] 인스타그램 추출 잡 API 연동 - 트러블슈팅

## 기록

### 2026-07-20 - 검증 루프 1회차: FR-05 툴팁 미구현 발견 → 노출 구현으로 스코프 조정

**상황**
- 서브 에이전트 유사도 검증 1회차 결과 API 명세 100%, FR-04 100%였으나 FR-05가 88.9%로 측정됐다.

**문제**
- Figma FR-05 두 화면(매칭실패/직접찾기)의 우측 상단 "정보 요청" 버튼 아래 노란 말풍선 툴팁("찾는 콘서트가 없다면?", Yellow30 배경 + 상단 화살표)이 구현에 없었다.

**원인**
- 기존 계획(LIVD-427 본편)에서 FR-06 관련 요소를 후속 이슈로 분리하며 툴팁 노출까지 함께 제외했다. 이번 검증 기준(디자인 유사도 98% 이상)에서는 정적 노출 요소라 범위에 포함되어야 했다.

**해결**
- `InstagramMatchSearchView`에 툴팁(Capsule Yellow30 + 삼각형 화살표, caption1Bold/black90, 버튼 하단 우측 정렬)을 두 진입 경로 공통으로 추가했다. 탭 액션(FR-06 요청 페이지)은 기존 결정대로 후속 이슈 TODO 유지.

**교훈**
- 화면 요소를 후속 이슈로 뺄 때 "액션"과 "정적 노출"을 구분한다. 노출만으로 완결되는 요소는 화면 구현 범위에 포함한다.

### 2026-07-20 - `Task.checkCancellation()` 컴파일 오류 (async 해석)

**상황**
- `ConcertMatchingRepositoryImpl`의 폴링 루프에 취소 전파용 `try Task.checkCancellation()`을 넣고 UserData 테스트를 실행했다.

**문제**
- `expression is 'async' but is not marked with 'await'` 컴파일 오류로 테스트 빌드가 실패했다.

**원인**
- 비제네릭 문맥에서 `Task.checkCancellation()`의 제네릭 인자 추론이 async 오버로드로 잘못 해석되었다.

**해결**
- `try Task<Never, Never>.checkCancellation()`으로 제네릭 인자를 명시해 해결. UserData 39개 테스트 통과 확인.

**교훈**
- 동시성 정적 API는 제네릭 추론이 모호할 수 있으니 컴파일 오류 시 타입 인자를 명시한다.

### 2026-07-20 - API 명세 문서 접근 불가 → 과거 세션 기록으로 명세 복원

**상황**
- 유저가 전달한 명세 문서 링크(인스타그램 추출 잡 API)로 명세를 확인하려 했다.

**문제**
- 문서 서비스 MCP 토큰이 만료(401)되었고, 브라우저 세션도 로그인되어 있지 않았으며, 공개 링크도 아니어서 문서에 직접 접근할 수 없었다.

**원인**
- 프로젝트에 설정된 문서 서비스 통합 토큰이 폐기된 상태였고, 브라우저 프로필이 해당 서비스에 미로그인 상태였다.

**해결**
- 2026-07-11 세션에서 동일 문서를 브라우저로 열람한 기록(추출 잡 생성·결과 조회 명세 전문, 요청/응답 스키마, 예외 응답)이 로컬 세션 히스토리에 남아 있어 이를 복원해 명세로 사용했다. 명세 요지는 계획 문서 배경에 옮겨 적었다.

**교훈**
- 외부 문서 기반 작업은 명세 요지를 계획 문서에 옮겨 적어 저장소 안에서 자급 가능하게 만든다. 만료 가능한 토큰·로그인 세션에 의존하지 않는다.
