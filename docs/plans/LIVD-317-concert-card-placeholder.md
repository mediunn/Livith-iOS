# 317 후속: 모달 내용과 화면 배치 책임 분리

## 배경
- 공통 컴포넌트의 외부 배치를 사용하는 화면으로 이동하는 작업의 후속이다.
- LivithDangerModal은 내용·입력 검증 외에도 전체 화면 중앙 정렬, 외부 좌우 24, 신고 모달의 키보드 회피와 제한 초과 토스트 위치를 처리한다.
- 사용자는 모달의 내용과 표시 컨테이너를 분리하는 방향에 동의했다. 구현 방식과 공용 배치 인터페이스도 사용자 승인을 받았다.

## 목표
- LivithDangerModal은 내부 여백 16과 문구·버튼·신고 입력·검증·콜백을 담당한다.
- 사용하는 화면이 외부 여백과 배치 동작을 지정하며 기존 화면 위치와 동작을 유지한다.

## 권한·범위
- 정본: 확인·취소 콜백, 신고 내용 전달, 200자 제한과 확인 버튼 활성 조건 유지.
- 정본: 외부 좌우 24와 중앙 배치는 모달 사용처에서 결정.
- 정본: 신고 모달은 기존처럼 키보드 높이의 절반만큼 위로 이동하고, 제한 초과 안내는 키보드 위 기존 위치에 표시.
- 정본: crossDissolve의 배경 탭 허용 정책과 전환 애니메이션 유지.
- 이번 범위 밖: 새로운 모달 디자인, 검증 정책 변경, 기존 스낵바 변경의 커밋·푸시, 다른 오버레이의 배치 정책 변경.
- 스낵바의 사용자 검증 완료 변경사항은 그대로 보존한다.

## 기술 결정
| 결정 사항 | 선택지 | 결정 | 근거 |
|-----------|--------|------|------|
| 화면 배치 | 각 화면에 GeometryReader·키보드 관찰 복사 / 전용 modifier | 전용 modifier (사용자 승인) | 반복 없이 사용 화면에서 배치 선택 가능 |
| 사용 형태 | 모달 생성 뒤 외부 여백과 배치를 명시 | `.padding(.horizontal, 24).livithModalLayout(avoidsKeyboard: true)` (사용자 승인) | 여백과 키보드 회피 책임이 사용처에서 보임. 확인 모달은 키보드 회피 기본 false |
| 입력 안내 상태 | 공용 배치 modifier로 전달 | 내부 PreferenceKey 메시지 전달 (사용자 승인) | 텍스트 검증은 모달에 남기고 화면 좌표는 배치 컨테이너가 담당 |

## 주의 사항
- 일반 모달을 포함하는 crossDissolve에는 새로운 배치 정책을 일괄 적용하지 않는다.
- 확인 모달은 키보드 높이 변화로 이동하지 않으며, 신고 모달의 키보드 관찰은 화면 표시 수명 동안만 유지한다.
- 텍스트 입력과 제한 초과 상태를 두 곳에서 독립적으로 계산하지 않는다.
- 확인·취소 버튼의 터치 영역과 모달 외부 탭 동작을 보존한다.
- DesignSystem에 단위 테스트 타깃이 없고 PreferenceKey·키보드 연결은 시스템 UI 배선이므로 tdd.md의 연결 구간 예외 적용. 새 테스트 타깃이나 생산 코드의 테스트 전용 인자를 추가하지 않고 실제 소스의 임시 시뮬레이터 검증으로 확인.
