# [#327] iOS 도메인 구조와 책임 재구성

## 배경

모델·에러·Repository를 각각 다른 디렉터리에서 찾아야 한다. 공연과 사용자의 계약에는 서로 다른 호출자가 쓰는 기능이 섞여 있다. 가입 단계와 캘린더 필터의 일부 업무 규칙은 Feature가 관리한다.

## 목표

- 업무 영역별로 모델·계약·에러를 함께 두고, Store는 자신이 쓰는 계약을 주입받는다.
- 변경 가능한 모델은 자신의 상태를 바꾸는 메서드에서 업무 규칙을 지킨다. 순수 조회 결과는 현재 형태를 유지한다.
- 서버 응답은 Data가 해석하고, 도메인 에러의 의미와 typed throws는 유지한다. 표시 문구와 재시도·토스트 선택은 Feature가 담당한다.

## 권한·범위

- 기준은 GitHub `develop`과 일치하는 `f538f1d3`이다. 승인받은 계획의 코드 기준점 `db34ce7e`에서 Projects와 Tuist 파일은 바뀌지 않았다.
- 단일 Domain 타깃, 기존 서버 API와 페이로드, 사용자 캐시 형식, 로그인 수단, 화면 문구와 사용자 흐름을 보존한다.
- 날짜 전용 타입, 공통 에러 타입, 새 모듈·의존성 도입은 별도 결정으로 둔다.

## 영향 범위

모든 경로는 `Projects/Domain/Sources/` 기준이다. 대응하는 Data 구현체·Assembler, App 등록 및 Feature/Shared의 Store와 테스트에 영향을 준다.

| 폴더 | Repository | 모델과 규칙 | 에러 |

## 기술 결정

| 결정 | 대안 | 결정·근거 | 상태 |
|---|---|---|---|
| 도메인 배치 | 기능별 타깃 분리, 기존 역할별 폴더 | 단일 타깃 내부의 업무별 폴더로 이동 | 합의 |
| 계약 분리 | Data 구현체도 동시에 분리 | 기존 구현체를 재사용하고 Store와 mock을 좁은 계약에 연결 | 합의 |
| 기존 공연 보조 메서드 | 공개 계약에서 제거, 가까운 책임에 유지 | 검색 섹션은 목록 계약에, 대표 셋리스트는 상세 계약에 유지. 호출자를 찾지 못한 상태에서 삭제하지 않음 | 적용 |
| 알림 계약 | 기존 계약 유지, 알림함·설정·푸시 토큰 분리 | 각각의 호출자가 분리되어 있으므로 기존 구현체를 세 계약에 등록. App과 AuthData는 푸시 토큰 계약만 사용 | 적용 |
| 공통 에러 표현 | 개별 enum 유지, 공통 실패 타입 조합 | typed throws와 개별 enum 유지. 같은 종류의 서버 실패에 기존 화면 문구가 달라서 공통 에러 타입으로 합치려면 별도의 결정이 필요함 | 이번 작업에서 유지 |

## 주의 사항

- `UserDiskCache`의 기존 인코딩 형식과 조회·강제 갱신 동작을 보존한다.
- 등록한 프로토콜마다 같은 구현체와 상태를 사용할 수 있도록 DI를 확인한다.
- `localizedDescription` 호출부는 대체 문구 매핑과 취소 여부를 검증한 뒤 이전한다.
- 기존 홈 진행 계획에서 보호하는 사용자 조회와 추천 노출, 캘린더 상태 규칙을 회귀 기준에 포함한다.

## 인수인계

화면 입력과 비동기 요청은 Feature가 담당한다. 모델은 입력 및 상태 전환의 유효성을 판단하며 네트워크 호출 없이 테스트할 수 있어야 한다.
