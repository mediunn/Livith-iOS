# [#334] 사용자 캐시 제거 및 토큰 기반 로그인 복원

## 배경

[이슈 #334](https://github.com/mediunn/Livith-iOS/issues/334). 현재 사용자 조회는 5분간 메모리의 `User`를 재사용하고 같은 값을 `UserDefaults.currentUser`에 저장한다. 앱 시작 시 이 키가 없으면 Keychain 토큰까지 삭제한다. 푸시 토큰 재등록도 이 키를 확인한다. 기존 설치의 사용자 데이터를 안전하게 지우려면 두 경로의 로그인 판단을 먼저 바꿔야 한다.

## 목표

- 사용자 조회를 호출할 때마다 서버에서 가져온다. 기존 설치를 업데이트해도 디스크에 사용자 사본이 남거나 다시 생성되지 않는다.
- 앱 시작 시 토큰 갱신에 성공하면 메인으로, 저장된 토큰이 없거나 갱신에 실패하면 로그인으로 이동한다. 재설치 후 Keychain에 토큰만 남은 경우에도 같은 기준을 적용한다.
- 로그인·가입·세션 복원 성공 후 FCM 토큰 등록을 시도한다. 로그아웃 상태에서 FCM 토큰이 발급되면 등록을 건너뛴다.
- 프로필에서 저장한 닉네임은 추가 조회 없이 홈에 반영한다. 늦게 도착한 사용자 조회 응답이 새 닉네임을 덮어쓰지 않는다.

## 권한·범위

- 합의한 범위는 Android의 서버 조회·로그인 복원·푸시 등록 동작과 iOS의 기존 `SessionNickname` 유지다.
- 홈 화면을 그리는 데 필요한 `HomeState.interest.user`, 다른 도메인의 캐시, HTTP 캐시 정책, Keychain 저장 형식은 변경 대상에서 제외한다.

## 작업 항목

1. [x] **로그인 복원과 푸시 등록.** `AppRootView.resolveLaunchRoute()`에서 로컬 사용자 조회와 그에 따른 토큰 삭제를 제거한다. 기존 `TokenManager.refresh()`의 결과로 분기한다. 로그인·가입 성공 시 `AuthRepositoryImpl`이 수행하는 등록을 유지하고, 복원 성공 경로에도 등록을 연결한다. Firebase 콜백은 로그인 세션을 확인하며, 복원 전에 콜백이 와도 복원 성공 후 등록 기회가 남아야 한다.
2. [x] **사용자 조회 통합.** `UserRepositoryImpl.fetchUser()`를 서버 조회로 통일한다. `refreshUser()`와 홈의 강제 조회 분기를 정리하고 Domain 계약·테스트 대역·참조 문서를 맞춘다. 홈·프로필의 장르/아티스트 저장 뒤 반환값을 버리던 캐시 갱신 호출을 제거한다. 홈의 사용자 조회와 닉네임 초기화는 한 요청을 사용한다.
3. [x] **로컬 사본 제거와 마이그레이션.** `UserDiskCache`, 로그인·가입의 사용자 저장, 닉네임·알림 설정 수정 시 로컬 사본 갱신을 제거한다. 앱 시작 시 구버전의 `currentUser` 키만 삭제한다. 키가 이미 없어도 안전하고 로그인 복원 결과와 무관하게 정리가 끝나야 한다.
4. [ ] **기능별 회귀 확인.** 홈·커뮤니티·알림 설정에서 사용자 조회가 필요한 경로와 선호 변경 후 재진입을 확인한다. 서버 실패를 성공으로 취급하거나 이전 계정 정보를 표시하는 경우가 없는지 점검한다.

## 영향 범위

App의 시작 경로와 푸시 서비스, AuthData·UserData·NotificationData의 저장소, Domain의 사용자 조회 계약 및 이를 호출하는 HomeFeature·UserFeature가 주요 변경 대상이다. ConcertFeature의 커뮤니티는 현재 사용자 ID를 조회하므로 검증 대상에 포함한다.

## 기술 결정

| 선택 사항 | 대안 | 결정·근거 | 확인 상태 |
|---|---|---|---|
| 로그인 복원 기준 | 설치별 로그인 표식 유지 | Keychain 토큰의 서버 갱신 결과를 사용한다. 재설치 후에도 동일하게 판단한다. | 합의 |

## 주의 사항

기존 토큰 갱신은 서버의 인증 거절 시 저장 토큰을 정리한다. 일시적인 네트워크 실패까지 토큰 삭제로 확대하지 않는다. FCM 등록 실패는 로그인 성공을 되돌리지 않는다.

## 인수인계

**후속 백로그 · 앱 서비스 소유권** — 별도 작업에서 `NotificationService.shared`와 `DeepLinkService.shared`를 제거하고 `AppDelegate`가 두 인스턴스를 보관하도록 한다. 외부 URL과 푸시 탭에서 전달한 링크를 메인 탭이 같은 인스턴스에서 소비하는지 확인한다.

구버전의 로그인 상태에서 앱을 업데이트하는 경우와 로컬 사용자 키 없이 Keychain 토큰만 남은 경우를 따로 확인한다. 전자는 데이터 정리, 후자는 복원 기준 변경을 검증한다.
